# Data model — schema version 1

This document defines Batch 2 SQL and all runtime queries. D1 stores text and image metadata. R2 stores image bytes. No public view writes data.

## Reading the definitions

Every column below is NOT NULL unless explicitly marked NULL. A column without a stated default must be supplied. `id` means INTEGER PRIMARY KEY, generated by SQLite when omitted; no AUTOINCREMENT. IDs are positive integers at the API boundary. Foreign keys are enabled. No application triggers are used.

`timestamps` expands to both `created_at INTEGER DEFAULT (unixepoch()) CHECK(created_at >= 0)` and `updated_at INTEGER DEFAULT (unixepoch()) CHECK(updated_at >= created_at)`. Both are Unix seconds. Every mutation explicitly updates updated_at; there is no automatic update trigger.

`status` on content expands to TEXT DEFAULT 'draft' CHECK(status IN ('draft','ready')). `live_at` expands to INTEGER DEFAULT 0 CHECK(typeof(live_at)='integer' AND live_at >= 0). Zero means ready content can appear immediately. `flag` means INTEGER DEFAULT 0 CHECK(value IN (0,1)). `order` means INTEGER DEFAULT 0 CHECK(typeof(value)='integer' AND value BETWEEN 0 AND 1000000).

`text(min,max)` means TEXT with a CHECK on length between those limits. Required names, titles, labels and alt text additionally reject blank trimmed strings. Optional text uses DEFAULT ''. `slug` means text(1,80), UNIQUE, lowercase ASCII letters/digits separated by single hyphens: no other characters, leading/trailing hyphens or double hyphens. SQL checks enforce those rules. Slugs are not automatically changed when titles change.

`url` means text(0,2048) DEFAULT ''. The API additionally permits only an empty value or an absolute http/https URL with a host and without embedded credentials. `phone` means text(0,24) DEFAULT ''; the API accepts an optional leading + and digits/spaces, then normalizes it. `platform` is TEXT in tiktok, instagram, facebook, youtube, website, whatsapp, other. Optional source_platform also permits '' and defaults to ''.

Every numeric column used as an integer has a typeof(column)='integer' check, except INTEGER PRIMARY KEY, which already enforces integer identity. Nullable numeric checks allow NULL. All text length limits are characters; HTTP body limits separately protect byte size.

| lookbooks | id; slug; title text(1,180); description text(0,5000) DEFAULT ''; creator_id INTEGER NULL DEFAULT NULL REFERENCES creators(id) ON DELETE SET NULL; is_featured flag; sort_order order; status; live_at; timestamps |
| tags | id; slug; label text(1,60) |

Reviews may describe a creator, an item, both, or neither. When both are supplied, the API requires the item's creator_id to match. Likes are a manually copied number, never a counter. All content types can exist without photos.

The house creator uses slug `sageworks-media`, name `SageWorks Media`, kind house, status ready. A partial unique index permits at most one house. The required core seed supplies that row; the API refuses deleting it, changing its kind, or creating another house. A unique index alone cannot guarantee that a row exists. The house can be edited and drafted like other creators; drafting it hides its associated public content.

## Media library

media_assets columns:

| Column | Type, default and constraint |
| --- | --- |
| id | INTEGER PRIMARY KEY |
| uuid | TEXT UNIQUE; exactly 36 characters; API-generated UUID |
| key_full | text(1,200) UNIQUE; server-generated R2 key |
| key_md | text(1,200) UNIQUE; server-generated R2 key |
| key_thumb | text(1,200) UNIQUE; server-generated R2 key |
| mime | TEXT CHECK IN ('image/webp','image/jpeg'); required |
| width | INTEGER CHECK BETWEEN 1 AND 1600; full image width |
| height | INTEGER CHECK BETWEEN 1 AND 1600; full image height |
| bytes_full | INTEGER CHECK BETWEEN 1 AND 2097152 |
| alt_text | text(1,240); nonblank; required |
| caption | text(0,2000) DEFAULT '' |
| credit | text(0,240) DEFAULT '' |
| source_platform | Optional platform DEFAULT '' |
| source_url | url DEFAULT '' |
| dominant_color | TEXT, required, no default; exactly # plus six hex digits; computed in the browser |
| focal_x | REAL DEFAULT 0.5 CHECK BETWEEN 0 AND 1 |
| focal_y | REAL DEFAULT 0.5 CHECK BETWEEN 0 AND 1 |
| status | TEXT DEFAULT 'active' CHECK IN ('active','archived') |
| uploaded_by | text(1,80); selected admin display name |
| created_at, updated_at | timestamps |

The three keys must be distinct, enforced by a table CHECK. Metadata describes the resized full image, with orientation already corrected by the browser. The other variants preserve its aspect ratio. The API verifies file dimensions from bounded image headers, MIME and magic bytes. It does not decode or resize images in the Worker.

Every upload creates three immutable objects: img/YYYY/MM/<file-uuid>.webp, img/YYYY/MM/<file-uuid>_md.webp and img/YYYY/MM/<file-uuid>_t.webp. JPEG uses .jpg. Year/month are UTC. Replacing a file uses a NEW file UUID and three new keys while preserving media_assets.id and media_assets.uuid. Existing links survive; old cached URLs cannot mask the new image.

Archive hides an image from the default picker, not from existing pages. Archived images remain usable when explicitly selected. Uploaded images are intended to be public; a draft or archive is not private storage. Hard deletion cannot retract copies already cached by visitors.

Each entity has at most 24 image-link rows, including cover/avatar/banner roles, enforced by its replace-set API. Empty sets are valid. List queries select only a cover, primary, avatar or first ordered image. Galleries are detail-only.

All tag-link columns are NOT NULL. The API accepts up to 12 distinct tags per entity. Removing a tag removes its associations, not content. No AI operations exist in this release.

## Plumbing

| Table | Complete columns and constraints |
| --- | --- |
| auth_attempts | ip_hash TEXT PRIMARY KEY NOT NULL CHECK length=64; fail_count INTEGER NOT NULL DEFAULT 1 CHECK BETWEEN 1 AND 5; window_start INTEGER NOT NULL CHECK >=0, no default |
| schema_meta | key TEXT PRIMARY KEY NOT NULL; value TEXT NOT NULL; neither has a default |
| media_cleanup | object_key TEXT PRIMARY KEY NOT NULL CHECK length BETWEEN 1 AND 200; created_at INTEGER NOT NULL DEFAULT (unixepoch()) CHECK >=0; not_before INTEGER NOT NULL CHECK >=0, no default |

01_schema.sql inserts schema_meta key schema_version, value '1'. auth_attempts stores keyed hashes, never raw IP addresses. Failed logins atomically reset an expired window or increment a live window, capped at five. Expired-record cleanup only runs during a failed login; successful login, logout and session checks write nothing.

media_cleanup is a durable queue for unneeded R2 keys. Before an upload, its new keys are queued with not_before one hour ahead. On success, insertion/update of media metadata and removal of these reservations share a D1 batch. Replacements and hard deletions queue old keys in that same batch. Uploads must finish their D1 commit within ten minutes or fail; expired upload reservations cannot later become live assets. Cleanup ignores any key still referenced by media_assets. Admin actions retry at most 20 due objects at a time. There is no cron and no public-path cleanup.

## Visibility, integrity and seeds

Posts/items/reviews/lookbooks require status ready and live_at <= the request's captured current Unix time. Creators have no live_at; ready creators are immediately public. Posts and items also require a ready parent creator. Hidden items never appear publicly; sold-out items may appear. Linked reviews require each non-null parent to be public. Lookbooks with a creator require that creator to be ready. These checks apply to lists, detail, share tags, related content and sitemap alike.

Deleting a creator with posts or items returns a conflict; move/delete those entries first. Optional references on reviews/lookbooks become NULL. Deleting any content removes its image links, never image files. Deleting media still used by any of the six image-link tables is blocked by foreign keys, including during concurrent saves.

Reset order: tag links; all six image-link tables; creator_links; reviews; posts; items; lookbooks; creators; tags; media_assets; site_slots; auth_attempts; media_cleanup; schema_meta. Reset is for an empty/disposable database only. D1 batches provide atomic writes; do not issue unsupported manual transaction commands. Use PRAGMA defer_foreign_keys only where needed inside a migration/reset operation, never as a substitute for valid references.

Core seed: six slots, eight tags (streetwear, all-black, maun, local-design, accessories, footwear, everyday, occasion), and one house creator. Demo seed: two explicitly fictional creators, three posts, three items, two reviews and one lookbook. Demo records start draft, use no invented real endorsements or seller URLs, and contain no images. Both seeds are rerunnable without overwriting edits. Files remain below 90 KB; every statement remains below 100 KB.
